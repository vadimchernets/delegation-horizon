# Acceptance card

*Paper: Section 6.1 (acceptance literacy) and Section 5.2 (what counts as a verified piece).*
*For: anyone about to hand a piece of work to agents. Fill it in before the hand-over, not after.*

A piece of work is verified only if "done" was stated in advance and checked by something the agents
could not see. This card is that statement. Keep it next to the log line for the piece.

| Field | Your answer |
|---|---|
| Piece (one coherent deliverable, not a slice of one) | |
| Domain | |
| Who will use the result, and what they will do with it | |
| Done means (three to five observable conditions) | 1. <br> 2. <br> 3. |
| Not done if (the failure you most fear) | |
| Check I will use: hidden tests / qualified reviewer / real use / another model family with sources I open myself | |
| Where the check lives, so the agents cannot see it | |
| Errors I planted in the task (Week-size pieces and above), sealed where | |
| Reference hours: how long a qualified specialist would need by hand, and who said so | |
| Irreversible parts (money sent, data deleted, messages to strangers) and the extra rule for them | |
| Date the hand-over starts | |

## After the work comes back

| Question | Answer |
|---|---|
| Did every "done" condition hold? | yes / no |
| Did the check pass without changing it after seeing the result? | yes / no |
| Were all planted errors caught? How many missed? | |
| My minutes of attention (planning, instructing, reading, checking, fixing) | |
| Outcome: accepted / rejected / abandoned | |

Then write the log line (`python3 tools/log_piece.py my-log.jsonl`). Rejected and abandoned pieces go in
the log too; they are part of the denominator.
